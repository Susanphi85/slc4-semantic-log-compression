# Examples

Two small archives you can open straight away, plus the source file for one of
them so the byte-exact claim can be checked rather than taken on trust.

| File | Contents |
|---|---|
| `logs-sample.slc4z` | 1 200 synthetic log records, 4 leaf schemas, 19 fields |
| `orders-sample.slc4z` | 1 200 rows of a synthetic orders table, packed from CSV |
| `orders-sample.csv` | the exact CSV the archive above was built from |

Everything here is synthetic and generated by code in this repository. Nothing
comes from a production system.

## In the terminal

```bash
node cli.mjs inspect examples/logs-sample.slc4z
```

`inspect` prints the record count, the number of leaf schemas, and the codec
chosen for every column with its share of the stream — which is the quickest way
to see *why* an archive came out the size it did.

To check the byte-exact round-trip for yourself:

```bash
node cli.mjs unpack examples/orders-sample.slc4z -o restored.csv
```

`restored.csv` is byte-for-byte identical to `orders-sample.csv`, including the
delimiter, the quoting of the one value containing a comma and quotation marks,
and the trailing newline. Compare them with `fc /b` on Windows or `cmp` on Unix.

Packing reports the same thing without needing a reference copy, because it
verifies before writing:

```bash
node cli.mjs pack examples/orders-sample.csv -o out.slc4z
#   304.0 KiB -> 18.4 KiB  (16.53x)
#   encode 0.31s, verify 0.07s, round-trip ok and byte-identical
```

With a standalone binary from a release, drop the `node cli.mjs` prefix:

```bash
slc4 inspect logs-sample.slc4z
```

## In Total Commander

Install the plugin as described in the main README, then press Enter on
`logs-sample.slc4z`. The archive opens like any other and shows two entries:

```text
sample.json                  the decoded payload
logs-sample.slc4-report.txt  the codec chosen per column
```

F3 on the second entry answers "why is it this size" without unpacking
anything. F5 extracts, Alt+F5 packs a selected `.json`, `.jsonl`, `.csv` or
`.sql` file back into an archive.

## In the browser

Serve `web/` (`npm start`), open it, and drop either archive onto the *Unpack*
tab. Nothing is uploaded — the codec and Zstandard both run locally, so the
same page works on production logs you would never send to a web service.

Dropping `orders-sample.csv` onto the *Pack* tab shows the other direction,
including the round-trip badge reporting byte-exact rather than value-level
fidelity.

## Regenerating these files

They are not hand-made; both come from the fixtures and the CLI:

```bash
node cli.mjs pack fixtures/sample.json -o examples/logs-sample.slc4z
node cli.mjs pack examples/orders-sample.csv -o examples/orders-sample.slc4z
```
